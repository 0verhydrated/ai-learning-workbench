## 글자 수나 단어 수가 토큰 수는 아닙니다

**토큰**은 토크나이저가 텍스트를 나누어 숫자 식별자로 표현한 단위입니다. 토크나이저에 따라 단어 하나, 단어 일부, 문장 부호, 바이트 등이 단위가 될 수 있습니다. 모델에는 학습 때 사용한 방식과 호환되는 토크나이저와 어휘가 필요합니다. 공백으로 문자열을 나누는 방법은 정확한 대체 수단이 아닙니다.[4]

이 차이는 이중 언어 앱에서 중요합니다. 같은 뜻의 영어와 한국어 문장이 같은 토큰 수를 사용한다는 보장은 없습니다. 한국어의 조사와 어미, 영어 합성어, 코드 식별자, 이모지, 언어가 섞인 문장은 서로 다르게 나뉠 수 있습니다. 글자 수나 영어 단어 수를 기준으로 한 간편 환산법으로 다른 언어의 요금을 정확히 예측할 수 없습니다. 실제 모델의 토크나이저나 업체의 토큰 계산 기능으로 대표 입력을 측정하세요. API가 메시지 형식과 도구 정의까지 계산한다면 그것도 포함해야 합니다.

예를 들어 “Please reset my password”와 “비밀번호를 재설정해 주세요.”를 비교해 보세요. 눈에 보이는 공백 수로 토큰 수를 추측하지 마세요. 토크나이저 이름, 두 문장의 토큰 수, 특수 메시지 토큰을 포함했는지를 기록합니다. 이는 측정 절차이지, 특정 언어가 언제나 더 비싸다는 주장이 아닙니다.

## 컨텍스트 창은 작업 예산입니다

**컨텍스트**는 특정 요청을 처리할 때 모델이 이용할 수 있는 정보입니다. **컨텍스트 창**은 그 작업 공간의 한도입니다. 프롬프트에는 마지막 질문 외에도 지침, 이전 대화, 도구 결과, 검색 문단, 멀티모달 입력이 들어갈 수 있습니다. 입력과 출력은 창을 함께 사용하지만 최대 출력 한도는 별도로 존재합니다. 추론 특화 모델은 내부 추론을 위한 공간도 필요할 수 있습니다.[5]

컨텍스트 창이 8,000토큰인 가상의 모델을 생각해 봅시다. 생성에 1,500토큰, 여유분에 500토큰을 남기면 입력 예산은 6,000토큰입니다. 지침이 700, 대화 이력이 1,800, 질문이 200, 검색 문단이 2,600토큰이라면 입력 합계는 5,300입니다. 계획한 입력 예산에는 700토큰이 남습니다. 여기에 900토큰짜리 문단을 추가하면 입력 자체는 8,000보다 작아도 계획한 예산을 200토큰 초과합니다.

다음 코드는 Python 3으로 오프라인에서 실행할 수 있습니다. 수치는 학습용 가상 데이터이며 실제 토크나이저 측정값이 아닙니다.

```python
window, generation, margin = 8000, 1500, 500
parts = {"instructions": 700, "history": 1800,
         "question": 200, "retrieval": 2600}
allowance = window - generation - margin
remaining = allowance - sum(parts.values())
print(allowance, remaining, remaining - 900)
assert (allowance, remaining, remaining - 900) == (6000, 700, -200)
```

여기서 생성 예산은 필요한 경우 내부 추론까지 포함하여 잡은 전체 예비량입니다. 같은 추론 토큰을 두 번 더하면 안 됩니다. 실제 계산 방식과 출력 한도가 뜻하는 범위는 API마다 확인해야 합니다. 예산에 여유가 있다고 해서 모델이 모든 세부 사항을 올바르게 활용한다는 보장도 없습니다.

## 저장, 압축, 캐싱은 서로 다른 문제를 풉니다

앱의 **기억**은 나중에 가져올 수 있도록 저장한 정보입니다. 사용자 선호, 대화 기록, 프로젝트 메모 등이 여기에 해당합니다. 저장된 정보가 모두 현재 컨텍스트가 되는 것은 아닙니다. 앱이 필요한 내용을 골라 넣거나, 모델이 그 내용을 가져올 수 있는 도구를 제공해야 합니다. 대화 식별자는 상태를 관리하는 장치이지 무제한 대화가 한 번의 요청에 들어간다는 증거가 아닙니다.

**문맥 압축**은 이전 내용을 더 작은 표현으로 바꾸는 과정입니다. 일반적인 요약에서는 예외 조건, 정확한 식별자, 실패한 시도, 주장의 출처가 사라질 수 있습니다. 어떤 서비스는 평범한 요약문 대신 별도의 압축 상태를 제공합니다. 어느 방식이든 기준이 되는 파일은 대화 밖에 보존하고, 정확한 세부 내용이 필요할 때 다시 가져오세요. “테스트 통과”라는 요약은 테스트 명령, 출력, 코드 리비전을 대신하지 못합니다.

**프롬프트 캐싱**은 조건에 맞는 동일한 프롬프트 접두부의 계산을 재사용합니다. 장기 기억도 아니고, 컨텍스트 창을 넓히는 기능도 아니며, 이전 답변을 그대로 돌려준다는 뜻도 아닙니다. 바뀌지 않는 지침을 앞에, 매번 바뀌는 작업 데이터를 뒤에 배치하면 재사용에 도움이 될 수 있습니다. 다만 적용 조건, 캐시 경계, 보존 시간, 요금은 업체와 모델에 따라 다릅니다.[6]
