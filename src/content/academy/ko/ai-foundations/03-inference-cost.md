## 응답 속도와 처리할 수 있는 양은 다릅니다

<strong>추론</strong>은 학습된 모델로 새 입력을 처리하는 일입니다. 얼마나 빠른지 살펴볼 때는 두 가지를 구분해야 합니다. <strong>지연 시간</strong>은 개별 요청에 걸린 시간이고, <strong>처리량</strong>은 일정 시간 동안 끝낸 작업의 양입니다. 첫 토큰까지 걸린 시간으로는 출력이 언제 시작되는지, 전체 지연 시간으로는 언제 끝나는지 알 수 있습니다. 스트리밍은 총계산량을 줄이지 않아도 화면이 빨리 반응하는 듯한 느낌을 줄 수 있습니다. 한꺼번에 많은 요청을 처리하는 시스템이라도 개별 사용자는 오래 기다릴 수 있습니다.

대기열부터 네트워크, 프롬프트 처리, 생성, 도구 호출, 검증까지 전체 경로에서 시간을 측정하세요. 출력 길이가 생성 지연 시간에 큰 영향을 주는 경우가 많아, 짧은 프롬프트에서 몇 단어를 빼기보다는 응답 형식을 간결하게 만드는 편이 더 도움이 될 수 있습니다.[7] 가장 빨랐던 시연만 기준으로 삼지는 마세요. 보통 얼마나 걸리는지, 느린 요청은 어느 정도인지도 기록해야 합니다. 비교할 때는 작업과 출력 길이를 맞추세요. 한 줄 답변과 긴 설명을 같은 작업량으로 볼 수는 없습니다.

## 샘플링 설정으로 사실 여부를 조절할 수는 없습니다

언어 모델은 다음에 올 토큰의 후보를 예측합니다. <strong>샘플링</strong>은 그중 하나를 고르는 과정입니다. temperature를 지원하는 모델에서는 이 값으로 선택 확률이 얼마나 집중되는지 조절할 수 있습니다. 보통 값이 낮으면 확률이 높은 후보를 더 자주 고르고, 높으면 더 다양한 후보를 선택합니다. 이 설정이 사실을 확인하거나 빠진 근거를 찾아 주지는 않습니다. 같은 오답을 거듭 고를 수도 있습니다.

temperature를 0으로 설정해도 정답이나 완벽한 재현성이 보장되지는 않습니다. 출력의 변화가 적은 설정이라도 호스팅 시스템, 모델 리비전, 수치 계산 구현이 달라지면 결과가 달라질 수 있습니다. 가능하면 모델 버전을 고정하고 프롬프트와 설정을 기록한 뒤 반복해서 실행해 확인하세요. 정확한 산술이 필요할 때는 계산기를 사용하고, 모델의 확신 정도로 계산 결과를 판단하지 마세요. temperature 자체를 제공하지 않는 모델도 있으니 다른 모델의 설정을 그대로 복사하기 전에 실제 API를 확인하세요.

## 가상의 요금을 정하고 계산해 보기

가상의 서비스가 캐시되지 않은 입력 100만 토큰에 2달러, 캐시된 입력 100만 토큰에 0.50달러, 출력 100만 토큰에 8달러를 청구한다고 해 봅시다. 실제 업체의 요금이 아닌 학습용 수치입니다. 계산을 단순하게 하기 위해 입력 토큰은 일반 입력과 캐시 입력 중 어느 한쪽에만 속한다고 가정합니다.

입력 2,000토큰 중 1,200토큰이 캐시되고 출력이 500토큰이라면 요청 하나에 0.0062달러가 듭니다. 같은 요청 1,000건은 6.20달러입니다. 캐시되지 않은 입력 800토큰, 캐시된 입력 1,200토큰, 출력 500토큰에 각각 요금을 곱한 뒤 더한 값입니다. 전체 입력 2,000토큰에 일반 요금을 매기고 캐시 요금을 또 더하면 중복 계산이 됩니다.

아래 코드를 `cost.py`로 저장한 뒤 `python3 cost.py`로 실행하세요. Python 표준 라이브러리만 사용합니다. Decimal 산술로 요금을 계산하면 같은 입력에서 같은 계산 결과를 얻을 수 있습니다. 그렇다고 모델이 생성하는 답변까지 매번 같아지는 것은 아닙니다.

```python
from decimal import Decimal as D

RATES = {"input": D("2"), "cached": D("0.50"), "output": D("8")}

def cost(input_tokens, cached_tokens, output_tokens, requests=1):
    counts = (input_tokens, cached_tokens, output_tokens, requests)
    if any(type(n) is not int or n < 0 for n in counts):
        raise ValueError("Counts must be nonnegative integers")
    if cached_tokens > input_tokens:
        raise ValueError("Cached tokens exceed input tokens")
    total = ((input_tokens - cached_tokens) * RATES["input"]
             + cached_tokens * RATES["cached"]
             + output_tokens * RATES["output"])
    return total * requests / D("1000000")

print(f"One request: ${cost(2000, 1200, 500):.4f}")
print(f"1000 requests: ${cost(2000, 1200, 500, 1000):.2f}")
assert cost(2000, 1200, 500) == D("0.0062")
```

실제 청구서에는 캐시 쓰기, 추론 토큰, 이미지, 저장 공간, 도구, 재시도 같은 다른 항목도 포함될 수 있습니다. 현재 약관을 확인하고 실제 사용량과 대조하세요. 이 예제로 계산 방식을 확인한 뒤, 실제 예산에는 사용할 서비스의 요금과 과금 항목을 적용하세요.

## 동시 실행을 늘리기 전에 처리 흐름을 점검하세요

프롬프트 캐싱은 조건에 맞는 접두부가 일치할 때 반복 입력에 드는 계산을 줄일 수 있습니다. 프롬프트가 비슷하다고 모두 캐시에 적중하는 것은 아닙니다. 야간 분류처럼 바로 응답을 받을 필요가 없다면 배치 처리를 검토할 수 있습니다. 서비스별 조건에 따라 비동기로 처리하는 방식입니다.[9] 결과가 다른 순서로 돌아와도 원래 요청과 연결할 수 있도록 요청 식별자를 보관하세요.

속도 제한은 요청 수와 토큰 수에 따로 적용될 수 있습니다. 작업자만 늘리면 처리량은 늘지 않고 제한 오류만 잦아질 수 있습니다. 동시 실행 수를 제한하고 응답 헤더를 확인하세요. 재시도할 수 있는 오류에는 무작위 지연을 섞은 지수 백오프를 적용하되 대기 시간에 상한을 둡니다. 결제나 할당량 문제라면 계속 재시도하지 말고 원인을 해결해야 합니다.[8]
