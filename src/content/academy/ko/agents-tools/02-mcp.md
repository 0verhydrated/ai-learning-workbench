## MCP가 정하는 것은 프로그램 사이의 통신 방식입니다

<strong>Model Context Protocol(MCP)</strong>은 AI 애플리케이션이 다른 프로그램과 컨텍스트를 주고받고 그 기능을 호출하는 방식을 표준화한 규약입니다. 어떤 모델을 쓸지, 계획을 어떻게 세울지, 행동 전에 승인을 받을지는 애플리케이션이 정해야 합니다. 서버를 연결하면 기능을 쓸 인터페이스가 추가됩니다. 그 자체로 지능이 생기거나 서버를 신뢰할 수 있게 되지는 않습니다. [1]

연결에 참여하는 구성 요소는 세 가지입니다.

- <strong>호스트(host)</strong>: 모델 사용, 권한, 연동을 조율하는 AI 애플리케이션입니다.
- <strong>클라이언트(client)</strong>: 호스트 안에서 서버 하나와의 연결을 관리합니다. 서버 두 개를 연결하려면 각각을 위한 클라이언트가 필요합니다.
- <strong>서버(server)</strong>: 기능을 제공하는 프로그램입니다. 로컬에서도 원격에서도 실행할 수 있으므로, 여기서 서버가 반드시 클라우드 컴퓨터를 뜻하지는 않습니다.

서버는 실행할 수 있는 <strong>도구(tools)</strong>, 컨텍스트 데이터인 <strong>리소스(resources)</strong>, 재사용할 수 있는 상호작용 틀인 <strong>프롬프트(prompts)</strong>를 제공할 수 있습니다. 문서 연동을 예로 들면 도구는 `search_docs`, 리소스는 버전별 가이드, 프롬프트는 “두 릴리스 비교하기” 템플릿에 해당합니다. 프롬프트 템플릿은 모델에 전달할 문구를 재사용하는 데 쓰며 그 자체가 실행 코드는 아닙니다. 검색은 데이터를 바꾸지 않더라도 기능을 호출하므로 도구에 속합니다. [1]

## 전송 방식과 버전을 확인하기

<strong>Stdio</strong>는 표준 입력과 출력으로 로컬 프로세스를 연결합니다. <strong>Streamable HTTP</strong>는 HTTP로 요청을 전달하고 필요하면 Server-Sent Events로 스트리밍합니다. 원격 서버는 흔히 HTTP를 쓰지만, 전송 방식만으로 접근 권한이 정해지지는 않습니다. 로컬 서버라도 사용자 계정으로 실행되면 민감한 파일이나 환경 변수에 접근할 수 있습니다. [1]

이 수업의 아키텍처 참고 링크는 <strong>2026-07-28</strong> 버전입니다. 여기서는 요청별 프로토콜·버전 메타데이터와 `server/discover`를 설명합니다. 서버는 discovery를 구현해야 하지만 클라이언트가 이를 반드시 먼저 호출해야 하는 것은 아닙니다. 예전 초기화 핸드셰이크를 복사해 현재의 모든 서버에 적용하지 마세요. 클라이언트 SDK와 서버, 지원 프로토콜 버전을 맞춰야 합니다. 아래 코드는 버전별 JSON-RPC 메시지 전체가 아닌 <strong>도구 정의만</strong> 보여 줍니다. [1]

## 실습 예제: 읽기 전용 릴리스 문서 서버

팀에서 공개 문서의 스냅샷을 제공하는 서버를 운영한다고 해 봅시다. 실제로 설치한 서비스는 아니며 설계를 설명하기 위한 예제입니다. 제공할 데이터는 다음과 같습니다.

```text
release-4/export: CSV export supports at most 100 rows.
release-4/auth: Export requires a signed-in account.
```

호스트는 서버를 활성화하기 전에 출처와 전송 방식, 요청하는 권한, 제공할 기능을 확인해야 합니다. 서버 계정은 이 문서 모음만 읽을 수 있게 제한하고, 쓰기 도구는 제공하지 않습니다. HTTP로 연결할 때는 해당 서비스가 문서화한 인증 절차를 따르고 필요한 최소 권한만 사용합니다. `docs:read`는 서비스에서 정의할 수 있는 권한 범위의 예시이며, MCP 공통 표준은 아닙니다. 토큰을 프롬프트나 예제, 소스 저장소에 넣지 마세요.

`tools/list`가 반환하는 도구 목록에는 아래와 같은 정의가 들어갈 수 있습니다.

```json
{
  "name": "search_docs",
  "description": "Search the published release-4 documentation.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "minLength": 1, "maxLength": 120},
      "limit": {"type": "integer", "minimum": 1, "maximum": 5}
    },
    "required": ["query", "limit"],
    "additionalProperties": false
  }
}
```

“250행을 한 번에 내보낼 수 있나요?”라는 질문이 들어오면 호스트는 도구 목록과 스키마를 확인한 뒤 `search_docs`를 대상으로 한 `tools/call`을 허용합니다. 전달할 인자는 `{"query":"CSV export row limit","limit":3}`입니다. 서버는 승인된 스냅샷만 검색하고 출처 식별자와 함께 내보내기 문단을 돌려줍니다. 이를 받은 모델은 “한 번에는 안 됩니다. release-4 문서의 제한은 100행입니다”라고 답할 수 있습니다. 이 과정은 <strong>설명을 위한 예시이며 실제 호출을 관찰한 기록은 아닙니다.</strong>

서버에서 리소스도 제공한다면 클라이언트는 `resources/list`와 `resources/read`로 원본 가이드를 읽을 수 있습니다. 다만 도구 결과에 식별자가 있다고 해서 곧바로 읽을 수 있는 MCP 리소스라고 가정해서는 안 됩니다. 답변에는 릴리스 이름을 남겨 어느 버전에서 확인한 제한인지 알 수 있게 하세요. 과거 문서만으로 현재 제품의 제한까지 단정해서는 안 됩니다.

## 연결했다고 신뢰할 수 있는 것은 아닙니다

인증은 누가 연결했는지 확인하는 절차이고, 인가는 어떤 작업과 데이터를 허용할지 결정하는 절차입니다. 스키마 검증으로 이 둘을 대신할 수는 없습니다. 도구 설명에 “읽기 전용”이라고 써도 쓰기가 차단되지는 않습니다. 실제 서버 구현과 계정 권한에서 쓰기를 막아야 합니다. 검색 결과에 프롬프트 인젝션이 들어 있을 수도 있습니다. 문서 속 지시를 다른 연동을 호출해도 된다는 허가로 받아들이지 마세요.

설정 키와 자격 증명을 저장하는 방식은 호스트마다 다릅니다. 그래서 이 수업에서는 어디에나 쓸 수 있는 설정 파일이나 설치 명령을 제시하지 않습니다. 연결하기 전에 사용할 호스트와 서버의 문서를 확인하세요.

## 연습: 서로 다른 세 가지 실패
