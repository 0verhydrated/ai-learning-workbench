## 에이전트가 아니라 통신 규약

<strong>Model Context Protocol(MCP)</strong>은 AI 애플리케이션이 다른 프로그램과 컨텍스트를 교환하고 그 프로그램의 기능을 호출하는 방식을 표준화합니다. 어떤 모델을 쓸지, 어떻게 계획할지, 행동에 승인이 필요한지는 정하지 않습니다. 이는 애플리케이션의 책임입니다. 서버를 연결하면 인터페이스가 추가되는 것이지 지능이나 신뢰가 자동으로 생기는 것은 아닙니다. [1]

구성 요소는 세 가지입니다.

- <strong>호스트(host)</strong>: 모델 사용, 권한, 연동을 조율하는 AI 애플리케이션입니다.
- <strong>클라이언트(client)</strong>: 호스트 안에서 서버 하나와의 연결을 관리하는 구성 요소입니다. 서버 두 개를 연결한다면 각각을 위한 클라이언트가 필요합니다.
- <strong>서버(server)</strong>: 기능을 제공하는 프로그램입니다. 로컬이나 원격에서 실행할 수 있으며 반드시 클라우드 컴퓨터를 뜻하지는 않습니다.

서버는 실행 가능한 <strong>도구(tools)</strong>, 컨텍스트 데이터인 <strong>리소스(resources)</strong>, 재사용할 상호작용 틀인 <strong>프롬프트(prompts)</strong>를 제공할 수 있습니다. 문서 연동이라면 각각 `search_docs`, 버전별 가이드, “두 릴리스 비교하기” 템플릿에 대응합니다. 프롬프트 템플릿은 실행 코드가 아니며, 읽기 전용 검색도 도구입니다. [1]

## 전송 방식과 버전을 확인하기

<strong>Stdio</strong>는 표준 입력과 출력을 이용해 로컬 프로세스를 연결합니다. <strong>Streamable HTTP</strong>는 HTTP로 요청을 전달하며 필요하면 Server-Sent Events로 스트리밍합니다. 원격 서버는 흔히 HTTP를 사용하지만 전송 방식 자체가 접근 권한을 정하지는 않습니다. 사용자 계정으로 실행된 로컬 서버도 민감한 파일이나 환경 변수에 접근할 수 있습니다. [1]

이 수업이 참조한 아키텍처 페이지는 <strong>2026-07-28</strong> 버전으로 연결됩니다. 이 버전은 요청별 프로토콜·버전 메타데이터와 `server/discover`를 설명합니다. 서버는 discovery를 구현해야 하지만 클라이언트가 반드시 먼저 호출해야 하는 것은 아닙니다. 예전 초기화 핸드셰이크를 복사해 모든 현재 서버에 적용하지 마세요. 클라이언트 SDK, 서버, 지원 프로토콜 버전을 맞춰야 합니다. 아래 코드는 버전별 JSON-RPC 메시지 전체가 아니라 <strong>도구 정의만</strong> 보여 줍니다. [1]

## 실습 예제: 읽기 전용 릴리스 문서 서버

팀이 공개 문서의 스냅샷을 제공하는 서버를 운영한다고 가정합시다. 실제로 설치된 서비스가 아니라 설계 예제입니다. 데이터는 다음과 같습니다.

```text
release-4/export: CSV export supports at most 100 rows.
release-4/auth: Export requires a signed-in account.
```

호스트는 활성화 전에 서버의 출처, 전송 방식, 요청 권한과 제공 기능을 확인해야 합니다. 서버가 사용하는 계정은 이 문서 모음만 읽도록 제한하고 쓰기 도구는 제공하지 않습니다. HTTP 연결은 해당 서비스가 문서화한 인증 절차와 최소 권한 범위를 사용합니다. `docs:read`라는 이름은 서비스가 정의할 수 있는 <strong>예시 범위이지 MCP의 공통 표준 범위가 아닙니다.</strong> 토큰은 프롬프트, 예제, 소스 저장소에 넣지 않습니다.

`tools/list`가 반환하는 도구에는 다음 정의가 들어갈 수 있습니다.

```json
{
  "name": "search_docs",
  "description": "Search the published release-4 documentation.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "minLength": 1, "maxLength": 120},
      "limit": {"type": "integer", "minimum": 1, "maximum": 5}
    },
    "required": ["query", "limit"],
    "additionalProperties": false
  }
}
```

“250행을 한 번에 내보낼 수 있나요?”라는 질문을 받으면 호스트는 도구 목록과 스키마를 확인하고 `search_docs`에 대한 `tools/call`을 허용합니다. 인자는 `{"query":"CSV export row limit","limit":3}`입니다. 서버는 승인된 스냅샷만 검색하고 출처 식별자와 함께 내보내기 문단을 반환합니다. 모델은 “한 번에는 안 됩니다. release-4 문서의 제한은 100행입니다”라고 답할 수 있습니다. 이는 <strong>설명을 위한 흐름이며 실제 호출을 관찰한 기록은 아닙니다.</strong>

서버가 리소스도 제공한다면 클라이언트는 `resources/list`와 `resources/read`로 원본 가이드를 읽을 수 있습니다. 다만 도구 결과의 식별자가 자동으로 읽을 수 있는 MCP 리소스가 된다고 가정하면 안 됩니다. 답변에 릴리스 이름을 남겨 과거 문서를 현재 제품의 사실처럼 전달하지 마세요.

## 연결했다고 신뢰까지 생기지는 않는다

인증은 누가 연결했는지 확인하고, 인가는 어떤 작업과 데이터가 허용되는지 결정합니다. 스키마 검증은 둘 중 어느 것도 대신하지 않습니다. 설명에 “읽기 전용”이라고 적는 것만으로 쓰기가 차단되지는 않습니다. 실제 서버 구현과 계정 권한이 쓰기를 막아야 합니다. 검색 결과에 프롬프트 인젝션이 있을 수도 있으므로 문서 속 지시를 다른 연동을 호출할 권한으로 취급하지 않습니다.

설정 키와 자격 증명 저장 방식은 호스트마다 다릅니다. 따라서 이 수업은 범용 설정 파일이나 설치 명령을 제시하지 않습니다. 실제 연결 전에는 선택한 호스트와 서버의 문서를 확인하세요.
