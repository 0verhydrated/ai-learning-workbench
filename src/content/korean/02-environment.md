## 도구와 프로젝트 구분하기

텍스트 편집기, 개발자 도구가 있는 브라우저, Git, 그리고 지원 중인 Node.js 버전이 필요합니다. 브라우저는 독서 목록을 실행합니다. Node는 개발 유틸리티를 실행하고, 나중에는 자동화 테스트도 실행합니다. Git은 의도적으로 선택한 파일 상태를 스냅샷(snapshot)으로 기록합니다. 편집기는 텍스트를 살펴보고 수정하는 데 도움을 줄 뿐, 어떤 프레임워크(framework)를 사용해야 하는지 결정하지 않습니다.

유료 코딩 도우미는 선택 사항입니다. 무료 서비스나 로컬 모델을 사용할 수도 있고, 도우미 없이 진행할 수도 있습니다. 이용 가능 여부, 사용량 제한, 개인정보 처리 조건은 서비스마다 다릅니다. 구독을 애플리케이션 구조의 일부로 여기지 말고 자신의 상황에 맞게 선택하세요. 서비스 제공자의 API 키를 독서 목록의 JavaScript 코드에 절대 붙여 넣지 마세요.

소프트웨어는 공식 배포처나 이미 신뢰하는 패키지 관리자(package manager)를 통해 설치하세요. 운영체제별 설치 안내를 따르고, PATH가 바뀌었다면 터미널을 다시 여세요. PATH는 셸(shell)이 명령어를 찾을 때 검색하는 디렉터리 목록입니다.

## 도우미에게 수정을 맡기기 전에 확인하기

다음 명령어를 직접 실행하고 실제 출력을 읽어 보세요.

```sh
node --version
npm --version
git --version
```

버전 번호가 출력되면 해당 명령어를 사용할 수 있다는 뜻이지, 환경 전체가 올바르다는 뜻은 아닙니다. 명령어를 찾을 수 없다면 정확한 오류와 운영체제를 기록하세요. 원인을 진단하는 대신 관리자 권한 명령어를 무작정 실행하지 마세요. 도우미에게 더 넓은 권한을 부여하기 전에 왜 변경이 필요한지 설명하도록 해야 합니다.

프로젝트 파일과 개인 문서가 섞이지 않도록 전용 디렉터리를 만드세요.

```sh
mkdir reading-list
cd reading-list
git init
```

편집기에서 `index.html`, `styles.css`, `app.js`를 만드세요. 이후 수업에서는 작은 모듈(module)과 테스트를 추가합니다. 이번 버전에는 프레임워크나 빌드 파이프라인(build pipeline)이 필요 없습니다. 파일 검색과 도우미의 권한 범위가 명확해지도록 이 디렉터리 자체를 편집기에서 여세요.

## 로컬 출처에서 파일 제공하기

HTML을 파일로 직접 여는 것과 HTTP로 제공하는 것은 다르게 동작할 수 있습니다. 특히 모듈과 저장소에서 차이가 날 수 있습니다. 로컬 정적 서버(static server)를 사용하세요. Python 3가 설치되어 있다면 다음 방법을 사용할 수 있습니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

`reading-list` 안에서 실행한 뒤 `http://127.0.0.1:8000`에 접속하고, 작업이 끝나면 Control-C로 종료하세요. 자기 컴퓨터를 가리키는 루프백(loopback) 주소에 바인딩(binding)하면 일반적인 네트워크 접근을 자신의 컴퓨터로 제한할 수 있습니다. 홈 디렉터리를 제공하지 마세요. 정적 서버는 제공하는 디렉터리 아래의 모든 파일을 노출할 수 있습니다.

Python을 사용할 수 없다면 신뢰할 수 있는 편집기의 서버 확장 기능을 사용하거나, Node용 정적 서버 패키지를 검토한 뒤 설치하세요. Node 자체에는 `node serve`라는 내장 명령어가 없습니다. `npx`를 사용하는 명령어는 패키지를 다운로드하고 실행할 수 있습니다. 패키지 이름을 읽고, 의도한 의존성인지 확인하세요.

호스트 이름(hostname)과 포트(port)는 중요합니다. `localhost:8000`과 `127.0.0.1:8000`은 서로 다른 출처(origin)이므로 localStorage를 공유하지 않습니다. 학습하는 동안 한 주소를 정해서 일관되게 사용하세요.

## 복구할 수 있는 스냅샷 남기기

첫 커밋(commit)을 만들기 전에 Git이 무엇을 기록할지 살펴보세요.

```sh
git status --short
git diff
git add index.html styles.css app.js
git diff --cached
git commit -m "Start reading list"
```

커밋하려면 Git 작성자 정보를 설정해야 할 수도 있습니다. Git의 안내를 따르고, 공개할 의도가 있는 이름과 정보를 사용하세요. 로컬 비밀 정보나 의존성 디렉터리가 생기면 제외 규칙을 추가하세요. 파일을 제외하도록 설정해도 기존 커밋에서 그 파일이 사라지는 것은 아닙니다.
