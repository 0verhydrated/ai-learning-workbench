## 한 사람에게 빠른가, 많은 요청을 빨리 처리하는가?

<strong>추론</strong>은 학습된 모델로 새로운 입력을 처리하는 일입니다. <strong>지연 시간</strong>은 개별 요청에 걸린 시간이고, <strong>처리량</strong>은 일정 시간 동안 끝낸 작업의 양입니다. 첫 토큰까지 걸린 시간은 출력이 시작되는 시점을, 전체 지연 시간은 출력이 끝나는 시점을 측정합니다. 스트리밍은 총계산량을 줄이지 않고도 화면이 빠르게 반응하는 느낌을 줄 수 있습니다. 많은 요청을 동시에 처리하는 시스템에서도 개별 사용자는 오래 기다릴 수 있습니다.

대기열, 네트워크, 프롬프트 처리, 생성, 도구 호출, 검증을 포함한 전체 경로를 측정하세요. 출력 길이는 생성 지연 시간의 큰 부분을 차지하는 경우가 많습니다. 짧은 프롬프트에서 몇 단어를 빼는 것보다 응답 형식을 간결하게 만드는 것이 더 도움이 될 수 있습니다.[7] 가장 빨랐던 시연만 보여 주지 말고 일반적인 응답 시간과 느린 요청의 수준도 기록하세요. 비교할 때는 작업과 출력 길이를 맞춰야 합니다. 한 줄 답변과 긴 설명은 같은 작업량이 아닙니다.

## 샘플링은 진실을 조절하는 설정이 아닙니다

언어 모델은 다음에 올 수 있는 토큰을 예측합니다. <strong>샘플링</strong>은 그 후보들에서 하나를 선택하는 과정입니다. 지원되는 모델에서 temperature는 선택 확률이 얼마나 집중되는지를 바꿉니다. 보통 낮은 값은 확률이 높은 후보를 더 선호하고 높은 값은 더 다양한 선택을 허용합니다. 사실을 확인하거나 빠진 근거를 검색하는 기능은 아닙니다. 모델은 같은 오답을 반복해서 선택할 수도 있습니다.

<strong>“temperature가 0이면 정답이고 완벽히 재현된다”</strong>는 생각은 오해입니다. 변화가 적은 설정도 호스팅 시스템, 모델 리비전, 수치 계산 구현을 넘어서는 보편적인 재현성 보장은 아닙니다. 가능한 경우 모델 버전을 고정하고 프롬프트와 설정을 기록한 뒤 반복 실행으로 확인하세요. 정확한 산술에는 모델에게 확신 있게 말하라고 요구하는 대신 계산기를 사용합니다. temperature를 제공하지 않는 모델도 있으므로 설정을 무작정 복사하지 말고 실제 API를 확인해야 합니다.

## 명시적으로 가정한 요금으로 계산하기

가상의 서비스가 캐시되지 않은 입력 100만 토큰에 2달러, 캐시된 입력 100만 토큰에 0.50달러, 출력 100만 토큰에 8달러를 청구한다고 가정합니다. 실제 업체 요금이 아니라 학습용 수치입니다. 이 단순한 서비스에서는 입력 토큰 하나가 두 입력 요금 구간 중 정확히 하나에만 속합니다.

입력 2,000토큰 중 1,200토큰이 캐시되고 출력이 500토큰인 요청은 0.0062달러입니다. 같은 요청 1,000건은 6.20달러입니다. 캐시되지 않은 입력 800, 캐시된 입력 1,200, 출력 500토큰에 각각의 요금을 적용해 더합니다. 입력 전체 2,000토큰에 일반 요금을 적용한 뒤 캐시 요금을 또 더하면 안 됩니다.

아래 코드를 `cost.py`로 저장하고 `python3 cost.py`로 실행하세요. Python 표준 라이브러리만 사용합니다. Decimal 산술은 요금 계산을 결정적으로 만들지만, 모델의 답변 생성까지 결정적으로 만들지는 않습니다.

```python
from decimal import Decimal as D

RATES = {"input": D("2"), "cached": D("0.50"), "output": D("8")}

def cost(input_tokens, cached_tokens, output_tokens, requests=1):
    counts = (input_tokens, cached_tokens, output_tokens, requests)
    if any(type(n) is not int or n < 0 for n in counts):
        raise ValueError("Counts must be nonnegative integers")
    if cached_tokens > input_tokens:
        raise ValueError("Cached tokens exceed input tokens")
    total = ((input_tokens - cached_tokens) * RATES["input"]
             + cached_tokens * RATES["cached"]
             + output_tokens * RATES["output"])
    return total * requests / D("1000000")

print(f"One request: ${cost(2000, 1200, 500):.4f}")
print(f"1000 requests: ${cost(2000, 1200, 500, 1000):.2f}")
assert cost(2000, 1200, 500) == D("0.0062")
```

실제 청구에는 캐시 쓰기, 추론 토큰, 이미지, 저장 공간, 도구, 재시도 등 다른 항목이 포함될 수 있습니다. 현재 약관을 확인하고 실제 사용량과 대조하세요. 가상 견적은 지출 상한을 보장하지 않습니다.

## 동시 실행을 늘리기 전에 흐름부터 고치세요

프롬프트 캐싱은 조건에 맞는 접두부가 일치할 때 반복 입력의 계산을 줄일 수 있습니다. 비슷한 프롬프트가 모두 캐시 적중으로 이어진다고 가정하면 안 됩니다. 배치 처리는 야간 분류처럼 즉시 응답이 필요하지 않은 작업에 적합합니다. 바로 받는 응답 대신 서비스별 조건에 따른 비동기 처리를 선택하는 것입니다.[9] 결과 순서가 바뀌어도 연결할 수 있도록 요청 식별자를 보관하세요.

속도 제한은 요청 수와 토큰 수에 각각 적용될 수 있습니다. 작업자를 늘리면 처리량 대신 제한 오류만 늘 수 있습니다. 동시 실행 수를 제한하고 응답 헤더를 확인하며, 재시도 가능한 오류에는 무작위 지연을 섞은 상한 있는 지수 백오프를 적용하세요. 결제나 할당량 문제는 끝없이 재시도할 것이 아니라 원인을 해결해야 합니다.[8]
