## 토큰은 글자나 단어와 다르게 셉니다

<strong>토큰</strong>은 토크나이저가 텍스트를 나눈 뒤 숫자 식별자를 붙여 표현하는 단위입니다. 어떤 토크나이저를 쓰느냐에 따라 단어 하나가 될 수도, 단어 일부나 문장 부호, 바이트가 될 수도 있습니다. 모델에 쓰는 토크나이저와 어휘는 학습 때 사용한 방식과 호환되어야 합니다. 단순히 공백을 기준으로 문자열을 나눠서는 정확한 토큰 수를 얻을 수 없습니다.[4]

두 언어를 쓰는 앱이라면 이 차이를 특히 살펴봐야 합니다. 뜻이 같은 영어 문장과 한국어 문장도 토큰 수는 다를 수 있습니다. 한국어 조사와 어미, 영어 합성어, 코드 식별자, 이모지, 여러 언어가 섞인 문장이 각각 다르게 나뉘기 때문입니다. 글자 수나 영어 단어 수로 대략 환산한 값을 다른 언어에 적용하면 요금을 정확히 예측하기 어렵습니다. 실제로 쓸 모델의 토크나이저나 업체의 토큰 계산 기능에 대표 입력을 넣어 측정하세요. API에서 메시지 형식과 도구 정의도 계산한다면 함께 포함해야 합니다.

예를 들어 “Please reset my password”와 “비밀번호를 재설정해 주세요.”를 비교해 보세요. 공백 수로 추측하는 대신 토크나이저 이름과 두 문장의 토큰 수를 기록하고, 특수 메시지 토큰도 포함했는지 적습니다. 이 비교는 해당 토크나이저에서 두 문장이 어떻게 나뉘는지 확인하기 위한 것으로, 특정 언어가 언제나 더 비싸다는 뜻은 아닙니다.

## 컨텍스트 창에 맞춰 예산을 잡으세요

<strong>컨텍스트</strong>는 요청을 처리할 때 모델이 이용할 수 있는 정보이고, <strong>컨텍스트 창</strong>은 그 정보를 담는 작업 공간의 한도입니다. 프롬프트에는 마지막 질문뿐 아니라 지침, 이전 대화, 도구 결과, 검색한 문단, 멀티모달 입력도 들어갈 수 있습니다. 입력과 출력이 이 공간을 함께 쓰며, 출력에는 별도의 최대 한도도 있습니다. 추론 특화 모델이라면 내부 추론에 쓸 공간도 필요할 수 있습니다.[5]

컨텍스트 창이 8,000토큰인 가상의 모델로 예산을 잡아 보겠습니다. 생성에 1,500토큰을 배정하고 여유분으로 500토큰을 남기면 입력에는 6,000토큰을 쓸 수 있습니다. 지침에 700, 대화 이력에 1,800, 질문에 200, 검색 문단에 2,600토큰을 쓰면 입력 합계는 5,300토큰입니다. 입력 예산에서 700토큰이 남습니다. 여기서 900토큰짜리 문단을 더 넣으면 입력 자체는 8,000토큰보다 적어도 계획한 예산은 200토큰 넘게 됩니다.

다음 코드는 Python 3으로 오프라인에서 실행할 수 있습니다. 수치는 학습용 가상 데이터이며 실제 토크나이저 측정값이 아닙니다.

```python
window, generation, margin = 8000, 1500, 500
parts = {"instructions": 700, "history": 1800,
         "question": 200, "retrieval": 2600}
allowance = window - generation - margin
remaining = allowance - sum(parts.values())
print(allowance, remaining, remaining - 900)
assert (allowance, remaining, remaining - 900) == (6000, 700, -200)
```

이 예제의 생성 예산은 필요한 경우 내부 추론까지 포함해 미리 확보한 양입니다. 같은 추론 토큰을 두 번 더하지 않도록 주의하세요. 실제로 무엇을 어떻게 계산하는지, 출력 한도에 어디까지 포함되는지는 API마다 확인해야 합니다. 문단이 모두 들어가더라도 답변에서 정책의 예외 조건을 올바르게 적용했는지는 따로 확인해야 합니다.

## 기억, 문맥 압축, 캐싱의 역할

앱의 <strong>기억</strong>은 나중에 다시 쓰려고 저장해 둔 정보입니다. 사용자 선호, 대화 기록, 프로젝트 메모 등이 여기에 해당합니다. 저장했다고 모두 현재 컨텍스트에 들어가지는 않습니다. 앱이 필요한 내용을 골라 넣거나 모델이 직접 가져올 수 있도록 도구를 제공해야 합니다. 대화 식별자가 있어도 마찬가지입니다. 상태를 관리할 수 있다는 뜻이지, 길이에 관계없이 대화 전체가 한 번의 요청에 들어간다는 뜻은 아닙니다.

<strong>문맥 압축</strong>은 이전 내용을 더 작게 표현하는 과정입니다. 보통의 요약에서는 예외 조건이나 정확한 식별자, 실패한 시도, 주장의 출처가 빠질 수 있습니다. 요약문 대신 별도의 압축 상태를 제공하는 서비스도 있습니다. 어떤 방식을 쓰든 기준 파일은 대화 밖에 보존해 두고, 세부 내용이 정확히 필요할 때 다시 가져오세요. “테스트 통과”라는 요약만 남겨서는 테스트 명령과 출력, 코드 리비전을 확인할 수 없습니다.

<strong>프롬프트 캐싱</strong>은 프롬프트의 앞부분인 접두부가 같고 조건도 맞을 때 그 계산을 재사용하는 기능입니다. 정보를 장기적으로 기억하거나 컨텍스트 창을 넓혀 주지는 않습니다. 이전 답변을 그대로 돌려주는 기능도 아닙니다. 고정된 지침은 앞에, 매번 바뀌는 작업 데이터는 뒤에 두면 계산을 재사용하는 데 도움이 될 수 있습니다. 적용 조건과 캐시 경계, 보존 시간, 요금은 업체와 모델마다 확인하세요.[6]
