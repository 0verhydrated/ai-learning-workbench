## 작업에 필요한 정보부터 고르기

스크린샷이나 막연한 설명만으로는 도우미도 프로젝트를 정확히 파악하기 어렵습니다. 지금 어떻게 구현되어 있는지, 어떤 동작을 바꾸려는지, 이미 정한 규칙 중 무엇을 지켜야 하는지 알려 주세요. 그렇다고 컴퓨터 전체를 열어 줄 필요는 없습니다. 작업에 필요한 범위로 접근을 제한하세요.

독서 목록의 동작을 고치려면 보통 폼 마크업, 상태의 데이터 구조, 관련 이벤트 핸들러, 렌더링 함수가 필요합니다. 새로고침 뒤에도 데이터를 유지하는 영속성을 다룰 때는 저장소 모듈도 살펴봐야 할 수 있습니다. 무관한 메모나 브라우저 쿠키, 배포용 인증 정보는 제목이 사라지는 원인을 설명하는 데 필요하지 않습니다.

모델이 한 번에 참고할 수 있는 범위, 즉 컨텍스트 윈도(context window)에는 한계가 있습니다. 도구가 앞서 받은 내용을 요약하거나 잘라내면서 예전 대화에서 정한 사항이 빠질 수도 있습니다. 계속 지켜야 할 프로젝트 결정은 짧은 파일에 남겨 두세요. 대화가 길어져도 다시 읽고 검토할 수 있습니다.

## 간결한 프로젝트 메모 작성하기

프로젝트 메모에는 다음과 같은 내용을 담을 수 있습니다.

```text
프로젝트: 로컬 독서 목록
기술 구성: 바닐라 HTML, CSS, JavaScript 모듈; 빌드 단계 없음
데이터: 책은 { id: string, title: string, read: boolean } 형태
저장소: localStorage 키 reading-list:v1 사용 예정
개인정보 보호: 계정, 분석 도구, 서버 데이터베이스 없음
규칙: 제목은 문자 그대로 렌더링; 키보드로 조작 가능한 네이티브 컨트롤 사용
검증: 순수 로직은 Node 테스트; DOM은 브라우저에서 확인
비목표: 동기화, 표지 다운로드, 추천
```

메모를 바꿀 때도 코드처럼 검토하세요. 요구 사항을 확인하는 자료이지만, 저장소의 다른 문서에 적힌 지시까지 승인해 주지는 않습니다. 자주 참조하는 메모에 오래된 결정이 남아 있으면 이후 작업마다 같은 잘못을 반복할 수 있습니다.

기능을 요청할 때는 이미 구현한 부분과 앞으로 할 일을 구분하세요. 예를 들어 첫 페이지에 `read` 속성이 있어도 읽음 상태를 전환하는 기능은 아직 없을 수 있습니다. 이를 뭉뚱그려 "읽기 상태를 지원한다"고 하면 도우미가 구현 범위를 잘못 이해할 수 있습니다.

## 증상을 이해할 수 있게 자료 보내기

버그를 보고할 때는 재현 순서, 기대한 동작과 실제 동작, 관련 오류 메시지 전체를 적으세요. 코드도 문제와 관련된 부분을 골라 보냅니다. 파일 이름과 줄 위치를 함께 적으면 찾기 쉽습니다. 다만 파일을 편집하면 줄 번호가 달라질 수 있습니다.

```text
작업: 새로고침하면 책이 사라지는 이유를 진단해 줘. 아직 수정하지 마.
관찰: 제목 두 개를 추가하면 새로고침하기 전까지는 잘 작동해.
예상: 저장 기능은 다음에 추가할 기능이며, 현재는 구현하지 않았어.
첨부: 현재 상태의 app.js와 index.html.
질문: 어떤 책임을 저장소 모듈로 옮기는 게 좋을까?
제약 조건: 기존 DOM 구조를 유지하고 패키지는 사용하지 마.
```

저장 기능이 미구현 상태라고 밝혔으므로, 도우미는 고장 난 코드를 찾기보다 저장 처리를 어디에 둘지 검토할 수 있습니다. 자료를 모으는 과정에서 버그 수정으로 생각했던 작업을 기능 추가로 다시 정의하게 될 수도 있습니다.

함수 하나를 붙여 넣을 때는 그 안에서 사용하는 외부 변수와 보조 함수도 알려 주세요. 자동으로 생성된 파일을 보낸다면 수정해야 할 원본 파일을 따로 짚어 주세요. 그렇지 않으면 다음 빌드 때 덮어써질 파일을 고칠 수 있습니다.

## 대화에 비밀 정보 넣지 않기

로그나 설정 파일을 공유하기 전에 토큰(token), 인증 헤더(authorization header), 비공개 URL, 이메일 주소, 사적인 책 제목이 있는지 살펴보세요. 민감한 값은 `REDACTED_TOKEN`처럼 명확한 대체 표시로 바꾸되, 문제를 이해할 수 있도록 주변 구조는 유지하세요.

숨김 파일이나 비공개 저장소에 넣었다고 비밀이 보장되지는 않습니다. 제외 규칙도 도우미의 파일 읽기까지 막아 준다고 가정해서는 안 됩니다. 접근 제어와 데이터 보관 정책은 도구마다 다릅니다. 가능하면 도구 설정으로 접근을 제한하고, 기밀 자료를 보내기 전에 제공자의 정책을 확인하세요.

인증 정보가 노출됐다면 메시지나 파일만 지워서는 해결되지 않습니다. 해당 서비스에서 폐기하거나 새 값으로 교체하고, 다른 곳에 복사되었을 가능성도 확인하세요. 이 독서 목록은 인증 정보 없이 작동하므로 이런 정보를 다룰 부담이 없습니다.

## 실습: 제공할 맥락 추리기

책의 상태를 전환하는 토글(toggle)을 눌렀는데 다른 책이 바뀝니다. 도움을 받으려고 스크린샷, 렌더링 함수, 관련 이벤트 핸들러, 예시 목록, 배포 토큰, 작업과 무관한 일기를 모았습니다. 무엇을 보내고 무엇을 뺄지 골라 보세요.

관련 상태와 이벤트 코드, 식별자가 서로 다른 항목으로 만든 짧은 가상 목록을 보내세요. 어떤 조작 요소를 눌렀는데 어느 항목이 바뀌었는지 순서대로 적습니다. 화면 배치가 이 어긋남을 설명하는 데 도움이 될 때만 스크린샷을 넣고, 토큰과 일기는 빼세요. 배열 순서를 원인으로 단정하지 말고 식별자 처리부터 추적해 달라고 요청합니다. 불필요한 개인 자료 없이도 무엇을 대조할지 구체적으로 알려 줄 수 있습니다.
